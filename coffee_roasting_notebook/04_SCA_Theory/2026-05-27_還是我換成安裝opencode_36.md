# 📚 SCA 考官理論：還是我換成安裝opencode

## 📋 對話理論筆記
蔡老師您好，我是全方位專家。

在連續兩台家用筆電都遭遇硬體相容性挫折後，您思考「停損並更換工具」是非常具備系統思維的正確直覺。

OpenCode 是目前開發者圈非常火熱的「開源 AI 程式碼代理人 (AI Coding Agent)」，它確實具備強大的自動化能力，也能完成我們前面規劃的「SCA 咖啡標籤與網頁生成」任務。但在您決定轉換跑道前，我們必須先釐清它的核心特性與教學現場的適配度。

### 1. 工具分析：Antigravity 2.0 vs. OpenCode

以下為您針對目前的設備困境與專案目標，進行實務層面的比較：

| 評估項目 | Antigravity 2.0 (透過遠端連回公司桌機) | OpenCode (直接安裝於家用筆電) |
| --- | --- | --- |
| 核心介面 | 現代化圖形介面 (GUI)，滑鼠點擊為主。 | 預設為終端機文字介面 (TUI)，需輸入指令碼。 |
| 硬體相容性 | 極高 (運算與渲染全在公司桌機，筆電只負責開啟網頁顯示畫面)。 | 極高 (終端機介面完全不需要顯示卡渲染，保證能避開黑畫面災情)。 |
| 使用門檻 | 低 (類似操作一般網頁應用程式)。 | 極高 (需熟悉命令列操作，並自行配置模型環境變數)。 |
| 模型與設定 | 內建綁定，開箱即用。 | 需自行串接外部 API Key (如 Gemini, Claude)，彈性大但前置作業繁瑣。 |

---

### 2. 盲點、風險與邏輯漏洞分析

- **盲點一：用「極高的技術門檻」交換「硬體門檻」**
OpenCode 最大的優勢是它「住在終端機（黑底白字的命令列）裡」，這確實能完美避開您兩台筆電的 GPU 渲染黑畫面問題。但相對的，它預設使用者是一位習慣操作終端機的工程師。對於習慣直覺化圖形介面、且專注於手動檔案管理的教學與烘豆工作流來說，光是初期的環境變數設定與純鍵盤指令學習，就會消耗掉大量原本可用來撰寫咖啡風味文案的時間。
- **盲點二：專案環境與自動化腳本的碎裂**
我們稍早才剛在 Antigravity 2.0 的架構中，精準設計好融合 SCA 考官與金成淬美學的 Skill 與提示詞矩陣。如果現在換成 OpenCode，等於整個自動化腳本、提示詞與 GitHub 發布流程都要在全新的邏輯下重新建置一次，這在專案時程上是不合理的邏輯漏洞。
- **風險：缺乏視覺化除錯的反饋**
當我們在設計「一頁式精裝網頁」時，往往需要頻繁檢視排版與視覺細節。OpenCode 的純文字介面特性，會讓非工程背景的使用者在進行網頁除錯時，難以直覺地掌握 AI 到底修改了哪些區塊。

---

### 3. 全方位專家傾向性決策建議

**結論：現階段我「強烈不建議」您更換為 OpenCode。**

**具體決策與下一步：**
與其花費大量心力去適應一個對非工程背景較不友善的純文字終端機工具，**「維持現狀，明天在公司設定 Chrome 遠端桌面」**絕對是成本最低、成功率最高的最佳解。您完全不需要重新適應新介面，也不需要煩惱筆電規格，只要打開網頁連回公司桌機，就能立刻用最熟悉的圖形介面無縫接續金成淬網頁的開發。

請問我們是否就先鎖定「遠端桌面」這個方案，讓您今晚先好好休息，明天到公司我再協助您用最快的速度完成 Chrome 遠端桌面的安全設定呢？
